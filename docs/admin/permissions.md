# 权限模型

ZViewer 的权限系统分为四个角色，从高到低分别是 **root（超级管理员）**、**admin（管理员）**、**user（普通用户）** 和 **guest（游客）**。下面这张表能让你一目了然地知道每个角色能做什么、不能做什么。

## 四层角色对比

| 功能 | root | admin | user | guest |
|---|---|---|---|---|
| 进入管理后台 | ✅ | ✅ | ❌ | ❌ |
| 审核用户注册 | ✅ | ❌ | ❌ | ❌ |
| 修改他人角色 | ✅ | ❌ | ❌ | ❌ |
| 删除任意用户 | ✅ | ❌ | ❌ | ❌ |
| 删除任意房间 | ✅ | ❌ | ❌ | ❌ |
| 创建房间 | ✅ | ✅ | 视设置而定 | ❌ |
| 完全控制自己的房间 | ✅ | ✅ | ✅ | ❌ |
| 加入房间观看 | ✅ | ✅ | ✅ | ✅ |
| 发送评论与弹幕 | ✅ | ✅ | ✅ | ✅ |
| 修改系统设置 | ✅ | ❌ | ❌ | ❌ |
| 检查并应用更新 | ✅ | ✅ | ❌ | ❌ |
| 管理服务器文件 | ✅ | ❌ | ❌ | ❌ |

> **简单记法**：root 拥有所有权限；admin 可以管理房间和更新，但不能管理用户；user 可以观看和互动，可能可以创建房间；guest 只能观看和互动，不能创建房间。

## 注册与审核流程

### 三种注册模式

管理员可以在后台「基础设置」中选择注册模式：

| 模式 | 效果 |
|---|---|
| **开放注册（open）** | 任何人注册后自动激活，直接成为 user 角色 |
| **审批注册（approval）** | 注册后进入待审核状态，需要 root 审核通过才能使用 |
| **禁止注册（closed）** | 关闭注册入口，新用户无法注册 |

### 注册步骤

1. 访问首页，点击「注册」按钮
2. 填写用户名和密码，提交
3. 根据注册模式不同：
   - **开放模式**：注册成功即激活，直接登录
   - **审批模式**：注册成功后会提示「等待审核」，登录后角色为 guest，功能受限
   - **禁止模式**：页面上看不到注册入口

### 审核操作（仅 root）

1. 进入管理后台 → 「用户管理」Tab
2. 找到状态为「待审核」的用户
3. 点击「审核通过」按钮，该用户将升级为正式 user

## 游客身份说明

### 自动分配

当你没有登录时访问 ZViewer，系统会自动为你分配一个**游客（guest）身份**。你不需要注册就能使用。

### 游客能做什么

- 加入已存在的房间，观看视频
- 发送评论和弹幕

### 游客不能做什么

- 创建房间
- 进入管理后台
- 修改个人资料

### 转为正式用户

如果你希望拥有更多功能，可以：

1. 点击页面上的「登录/注册」
2. 注册一个新账号（如果注册模式为开放，即刻成为 user）
3. 登录后自动获得更多权限

## 房间创建权限

管理员可以在「基础设置」中设置谁可以创建房间：

- **仅管理员（admin-only）**：只有 root 和 admin 角色可以创建房间
- **所有用户（all-users）**：user 角色也可以创建房间

游客在任何情况下都不能创建房间。

## 认证机制简述

ZViewer 使用**双令牌**机制来保证安全：

- **Access Token（访问令牌）**：短期有效（默认 15 分钟），用于验证每一次请求
- **Refresh Token（刷新令牌）**：长期有效（默认 7 天），用于在访问令牌过期后自动续期

这些令牌通过 **httpOnly Cookie** 存储在浏览器中，普通 JavaScript 无法读取，有效防止 XSS 攻击窃取令牌。

简单来说：你登录一次，系统会记住你一段时间，期间不需要反复输入密码。

## 常见问题

### 注册后不能创建房间

可能的原因：

1. 你的角色是 **guest**（待审核或刚注册）。需要 root 在后台审核通过后升级为 **user**
2. 房间创建权限设置为「仅管理员」，而你是 user 角色
3. 注册模式为「开放注册」但系统未正确激活——请联系管理员检查

### 如何让用户成为管理员？

只有 **root** 可以提升其他用户为管理员：

1. 进入管理后台 → 「用户管理」Tab
2. 找到该用户
3. 点击「修改角色」，选择 admin
4. 保存

### 忘记 root 密码怎么办？

如果丢失了 root 账户的密码，可以通过以下方式恢复：

1. 如果服务器上有命令行访问权限，可以执行重置脚本或直接修改数据库
2. 如果在部署时设置了环境变量或初始配置，参考部署文档中的重置方式
3. 联系服务器运维人员，通过数据库直接修改用户密码（需要了解数据库操作）
