# 语音聊天链路

语音不参与播放同步，走与屏幕共享同一条 Piik 信令（`/signal`）与同一棵客户端树。功能说明见[功能说明](/basic/features)，端口映射见[安装与部署](/basic/install)。

## 音频由谁承载

语音是**成员之间直连**：房主为树根，观众按服务端下发的边与上游建立 WebRTC 连接，音频不经过服务器，也不做服务端混流。

后端只做四件事：签发房间凭证、决定树的边、校验禁言与踢人权限、在成员掉线时改派上游。

```
浏览器 ── POST /api/voice/piik/session ──▶ 后端（3333，签发 token / grant）
   │
   └─ /signal（WebSocket）── 认证、建边、转发 room-voice-* 帧
         └─ 成员之间 P2P 音频（房主为树根）
```

同一间 ZViewer 房间对应一个 Piik 房间码，共享与语音共用它。

## 凭证与身份

| 身份 | 凭证 | 说明 |
|---|---|---|
| 房主 | `token` | 调用时顺带建出房间，房主即树根 |
| 观众 | `viewerGrant` | 房主还没进语音时返回 409，稍后重签 |

凭证只经带鉴权的 REST 下发；`/signal` 升级时另带一枚短期 HttpOnly 站点通行证，浏览器拿不到别的房间的凭证。

## 采集与管控

麦克风经 `getUserMedia` 采集，开启回声消除、降噪与自动增益，强制单声道。音量分两层：全局音量 × 单成员音量，结果写进该成员的 `<audio>`。

自闭麦只把发布轨 `enabled` 置 false；管理员禁言与踢人走 `room-voice-command`，服务端校验 root / 房主 / 房管身份后下发。被禁言端锁定麦克风并提示，解禁自动恢复。

## 拓扑与恢复

- 树的边由服务端决定，客户端只在被指定为发起方时发 offer。
- 断线后重新签一次凭证即可回到同一棵树；上游掉线时服务端改派新的上游。
- 只有一位成员时按已连通处理，不显示「连接中」。
- 语音面板实时显示 ICE 实际选中的线路。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 点加入语音一直转圈 | `/signal` 未反代或 WebSocket 被拦 | 反代放行 `/signal` 的 Upgrade |
| 提示稍后再试 | 房主还没进语音 | 等房主先进语音 |
| 能听到但对方听不到 | 上行被防火墙拦截 | 检查本机 UDP 出网，必要时改走 TCP |
| 听不到别人声音 | 发布方没给该成员建边 | 看语音面板成员状态 |
| 两端都在对称 NAT | 打不出直连 | 换一侧网络再试 |

## 常量速查

| 常量 | 值 |
|---|---|
| 信令路径 | `/signal`（WebSocket） |
| 语音凭证端点 | `POST /api/voice/piik/session` |
| 媒体端口 | `3333/udp` + `3337/tcp`（自建媒体面，仅供旧链路） |
| 麦克风参数 | 单声道，回声消除 + 降噪 + 自动增益 |
| 管理权限 | root / 房主 / 房管 |
