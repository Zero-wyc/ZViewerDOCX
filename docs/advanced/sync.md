# 房间同步逻辑

房间实时同步全部走 Socket.IO。连接建立时经 JWT 鉴权中间件（`io.use`），token 无效直接拒绝握手，因此 WebSocket 与 REST 共用同一套身份体系。

## 角色与状态广播

- **房主是唯一的同步源**。房主操作（播放 / 暂停 / 跳转 / 倍速 / 切换影片）→ 后端写入房间状态 → `io.to(roomId).emit` 广播 → 观众端播放器对齐（seek + play/pause）。
- 服务器持有房间状态的**权威副本**。房主短暂断线时由服务器继续维持最后状态，观众不中断；房主重连后从服务器取回状态继续担任同步源。
- 房主主动离开后房间进入宽限期保持运行，观众可继续观看或自主控制；房主离线超过 10 分钟，后端自动关闭房间并通知全员。

## 控制权申请

1. 观众发起申请（暂停 / 继续 / 切歌 / 调进度 / 添加歌曲）。
2. 后端将申请转发给房主，房主播放器左上角收到通知。
3. 房主同意后，该观众获得临时控制权，操作走与房主相同的事件通道。
4. 房主可随时收回；开启「自动通过」后申请直接生效。

## 自主控制模式

房主离线期间，观众端进入自主控制模式：直接控制**本地播放器**，不经过服务器广播（避免多观众互相打架）。房主重连后自动恢复申请模式。

## 影片切换与资源清理

- 切换影片后观众端按新的直接地址重建播放流。
- 切换时**无条件取消进行中的内嵌字幕提取拉流**——否则旧影片的提取流会继续经服务器中转，产生持续的无用流量。

## 观众加入

三种方式：房间号、房间列表、分享链接。房间开启密码或审批时，加入前需输入密码或等待房主同意。进房时后端下发当前影片与播放状态，观众端直接对齐（含一起听的歌单即时同步）。
